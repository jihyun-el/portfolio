## 문제 정의

글자가 있는 사진과 한국어 질문을 받아 보기 a~d 중 정답 하나를 고르는 4지선다 VQA. 순위는 정확도로 결정

SSAFY 16기 2회차 AI 챌린지 "텍스트 이미지 기반 질의응답 모델 개발"입니다. 사진 한 장, 한국어 질문, 보기 4개가 주어지고 모델은 정답 보기의 글자 하나를 냅니다. 예: "표지판은 어디로 향하는 길을 안내하고 있나요?" a. 역삼 b. 선릉 c. 사상 d. 강남 (정답 c)

| 항목 | 내용 |
|---|---|
| 데이터 | train 6,714문항, test 6,714문항. 데이터 수집 미션으로 모은 사진을 4지선다 문제로 가공 |
| 평가 | 리더보드 정확도. Public은 test의 절반(3,357문항), Private은 나머지 절반. 재현성과 효율성, 게시판 글, 발표를 따로 평가 |
| 규칙 | 공개된 사전학습 모델과 LoRA·양자화 허용. 외부 API 추론 금지. 하루 20회 제출 |
| 장비 | 팀원 PC의 RTX 5060 Ti 16GB, Colab A100 80GB |

문항 대부분은 간판·메뉴판·가격표·안내문의 글자를 읽어야 풀립니다. 함께 제공된 dev 2,683문항은 정답 열 다섯 개 중 네 개 이상이 일치하는 문항이 없어 학습과 검증에서 제외했습니다.

## 실험 설계
<!-- anchor: experiments -->

출발점 모델과 데이터 분할(같은 사진은 한쪽에만)을 고정하고 가설을 팀원 4명에게 OCR·모델 크기·해상도·앙상블 축으로 배분. 모델 크기 × 해상도 **2×2 교차**로 두 효과를 분리

팀원마다 다른 조건에서 출발하면 어느 변경이 점수를 올렸는지 알 수 없습니다. 세 가지를 고정했습니다.

- **출발점**: Qwen3-VL 4B를 4비트로 올리고 LoRA를 1에폭 학습. 자체 검증 90.41%, Public 0.89037, 16GB GPU 한 장에서 43분
- **데이터 분할**: 학습 4,297 / 자체 검증 1,074 / 최종 확인 1,343문항. 같은 사진의 문항은 한쪽에만 두어 검증 점수가 부풀지 않게 함
- **한 번에 한 축**: 출발점에서 한 가지만 변경. 한 번 실행하면 학습, 검증, 제출 파일까지 나오는 실행 패키지를 만들어 팀원 4명이 각자 PC에서 병렬로 실행

모델 크기(4B, 8B)와 추론 해상도(512², 768²)는 네 조건을 모두 제출해 따로 쟀습니다. $s$는 Public 점수입니다.

<!-- figure:vqa-matrix -->

$$
\begin{aligned}
\text{해상도 효과} &= s_{\text{4B},768} - s_{\text{4B},512} = +3.99\,\%\text{p} \\
\text{모델 크기 효과} &= s_{\text{8B},512} - s_{\text{4B},512} = +2.23\,\%\text{p} \\
\text{겹침} &= (s_{\text{8B},768} - s_{\text{4B},768}) - (s_{\text{8B},512} - s_{\text{4B},512}) \\
&= -0.03\,\%\text{p}
\end{aligned}
$$

겹침이 0에 가까워 두 효과를 독립으로 보고 함께 적용했습니다(8B, 768², Public 0.95233). OCR 결과를 입력에 더하는 축은 자체 검증 +0.47%p였고 95% 신뢰구간이 0을 포함해 기각했습니다.

## 모델 학습

4비트 QLoRA에서 Qwen3.5-27B·Qwen3.8-27B·Gemma 4 31B의 BF16 LoRA로 전환. 보기 순서 섞기와 보기 확률 채점을 적용

초반에는 32B 모델을 4B·8B와 같은 방식(4비트 LoRA)으로 학습했습니다. Public 0.95621로 8B의 0.95680과 같은 수준이었고, 학습으로 더 맞힌 문항은 4B가 72개, 8B가 34개, 32B는 0에 가까웠습니다. 이때는 모델이 크면 학습으로 얻는 몫이 사라진다고 해석했습니다.

대회 게시판의 사례를 모으니 학습 이득이 없던 경우는 모두 4비트 학습이었고, 이득을 본 경우는 원래 정밀도(BF16) 학습에 보기 순서 섞기를 썼습니다. 원인을 모델 크기가 아니라 4비트 학습과 고정된 보기 순서로 보고 다시 학습했습니다. 구성은 상위 팀이 게시판에 공개한 뼈대(27B 학습, 보기 순서 섞기, 정답 글자 손실, 세 모델 평균)를 따랐습니다.

| 항목 | 설정 |
|---|---|
| 모델 | Qwen3.5-27B, Qwen3.8-27B, Gemma 4 31B |
| 정밀도 | BF16, 양자화 없음 |
| LoRA | rank 16, alpha 32, dropout 0.05. 언어 모델 층에만 적용하고 이미지 인코더는 고정 |
| 최적화 | AdamW, 학습률 5e-5에서 선형 감소, 워밍업 3%, 2에폭 |
| 데이터 | 학습할 때마다 보기 순서를 섞고 정답 글자도 함께 이동 |
| 손실 | 정답 글자와 종료 토큰에만 적용 |

자체 검증 1,074문항에서 Qwen3.8은 999 → 1,040문항, Qwen3.5는 1,029 → 1,040문항을 맞혔습니다. Gemma 4는 Public에서 0.95501 → 0.96455(+32문항)였습니다.

학습 해상도를 512²에서 768²로 올린 실험은 Public +7문항으로 효과가 없었습니다. 이미지 인코더를 고정하고 LoRA를 언어 모델 층에만 붙였기 때문으로 보고, 확대 입력은 추론에서만 썼습니다.

추론에서는 답을 글로 생성하지 않고 정답 자리에 a, b, c, d가 올 확률을 읽습니다. 형식이 깨진 답이 나오지 않고 확률을 그대로 평균할 수 있습니다. 보기를 한 칸씩 돌린 순서들과 여러 입력 해상도로 채점해 평균하고, 세 모델의 로그 확률을 평균해 가장 높은 보기를 고릅니다.

$$
\begin{aligned}
\bar{p}_{m,r}(k) &= \frac{1}{|\Pi_r|}\sum_{\pi \in \Pi_r} p_{m,r,\pi}(k) \\
s_m(k) &= \frac{1}{|R_m|}\sum_{r \in R_m} \log \bar{p}_{m,r}(k) \\
\hat{y} &= \arg\max_{k} \frac{1}{3}\sum_{m=1}^{3} s_m(k)
\end{aligned}
$$

$p_{m,r,\pi}(k)$는 모델 $m$이 해상도 $r$, 보기 순서 $\pi$에서 보기 $k$에 준 확률을 원래 보기 순서로 되돌린 값입니다. 결합 방법은 다수결, 확률 평균, 로그 확률 평균을 비교해 정했습니다. 로그 확률 평균이 확률 평균보다 자체 검증과 Public에서 각각 3문항 많았습니다.

## 실행 검수

설정에서 해상도를 바꿨는데 학습 코드가 고정 해상도를 쓰던 문제를 발견. 실제 입력 해상도 출력과 모델 해시 대조를 추가

팀원이 768² 학습 조건으로 1시간을 돌린 결과가 기존 모델과 점수가 소수점까지 같았습니다. 모델 파일(adapter)의 해시도 같았습니다. 설정 파일의 해상도 값을 학습 코드가 읽지 않고 512²로 고정해 쓰고 있었습니다.

실행 패키지는 팀원 모두가 쓰므로, 설정 파일에 적힌 값 대신 실제로 실행된 값을 확인하도록 바꿨습니다.

- 학습을 시작할 때 실제 입력 해상도를 출력
- 결과 모델의 파일 해시를 기존 모델과 비교
- 추가 채점 전에 16문항을 기존 조건으로 다시 채점해 저장된 확률과 대조(차이 0.0)
- 큰 GPU 실행 전에 실행할 ZIP과 노트북을 CPU에서 불러와 실행 경로를 검사

## 평가 규칙

앙상블 규칙과 채택 기준을 점수를 보기 전에 코드로 고정. 자체 검증 세트를 반으로 나눠 양쪽 모두 손해가 없을 때만 채택

Public 점수는 하루 20회까지 볼 수 있어, 점수를 본 뒤 규칙을 고르면 Public에만 맞춘 답안이 됩니다. 채택 기준, 결합 규칙, 다시 채점할 문항 목록을 결과 전에 코드로 커밋했습니다.

- **절반 검증**: 추론 방식을 더할 때는 자체 검증 세트를 번호순으로 반씩 나눠, 앞·뒤 절반 모두 손해가 없고 전체가 1문항 이상 늘 때만 채택
- **우연으로 날 수 있는 차이**: 두 답안이 $n$문항에서 다르면 약 $\pm 2\sqrt{n/2}$문항(95%)은 우연으로 날 수 있다고 보고, 이 범위를 넘을 때만 효과로 인정
- **기각한 실험도 기록**: 학습 해상도 변경, 타일링, 추가 에폭은 결과와 함께 남김

Qwen의 3배 확대 입력이 한 예입니다. Qwen3.5는 앞·뒤 절반에서 +1·+2문항으로 통과했고, Qwen3.8은 −1·−1문항으로 탈락했습니다.

최종 두 답안 중 하나는 세 모델의 로그 확률 평균이라는 미리 정한 규칙으로 만들었습니다. 다른 하나는 여기에 초반 다수결 답을 약한 한 표로 더한 것으로, Public 점수를 본 뒤 고른 결합입니다. Private에서 0.97855를 낸 쪽은 뒤의 답안이었고, 규칙 답안과의 차이는 2~4문항이었습니다. 후반의 BF16 학습과 보기 순서 섞기는 함께 바꾼 조건이라 하나의 변경으로 기록했습니다.
