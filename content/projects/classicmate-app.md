## 악보 앱의 상태를 지키기

2025년 9월부터 2026년 7월까지 ClassicMate 초기팀에서 개발총괄을 맡았습니다. Flutter·Supabase로 악보 앱을 개발하고 iOS·Android에 출시했습니다. 이 기간은 초기팀 참여 경험이며 앱의 Git 개발 기록은 2025년 12월부터입니다.

PDF 원본 좌표를 기준으로 필기를 저장하고 페이지별 오버레이로 표시했습니다. 기기 간 변경은 페이지 단위 3-way merge로 다뤘습니다.

화면 크기와 확대 배율에 따라 달라지는 화면 좌표를 저장하면 다른 기기에서 필기가 어긋납니다. PDF 원본 좌표를 저장하고 표시할 때 화면 변환을 적용했습니다. 필기를 페이지별로 나눠 악보 열람과 기기 간 변경을 함께 다룰 수 있도록 했습니다.

## 서버가 정하는 소유권과 잔액

클라이언트 화면의 상태와 서버의 소유권이 어긋나지 않도록 계정·캐시·동기화의 경계를 다뤘습니다. 탈퇴·재가입 과정에서는 남은 캐시가 새 계정으로 올라가는 경로를 추적하고 계정 전환 정리와 서버 검증을 보강했습니다.

한 사례에서는 탈퇴·재가입 후 31초 안에 이전 소유권 133건이 새 계정에 복제됐습니다. 기기에 남은 캐시, 계정 전환을 통과한 동기화, 서버의 소유권 확인 부족이 연결된 결과였습니다. 화면에서 캐시를 지우는 처리와 서버 쓰기 권한의 확인을 함께 봐야 했습니다. 로그아웃뿐 아니라 토큰 만료 같은 암묵적 계정 종료에서도 필기 데이터 정리를 보강했습니다.

인앱 결제에서는 외부 거래 ID의 유일성 제약과 조건부 갱신으로 중복 지급을 막는 구조를 설계했습니다. 유료·보상·환불 부채를 구분한 지갑 회계를 사용했습니다. 결제 백엔드의 운영 배포와 실제 유료곡 판매 개시는 별개의 사실입니다.

거래의 제공자와 외부 ID 조합을 고유하게 두고, 조건에 맞는 상태에서만 갱신하도록 했습니다. 같은 구매 검증이나 환불 요청이 다시 들어와도 이미 처리한 거래를 새 거래처럼 지급하지 않도록 경계를 설계했습니다. 유료 잔액, 보상 잔액, 환불 부채를 분리해 취소와 사용의 순서도 회계에 반영했습니다.
