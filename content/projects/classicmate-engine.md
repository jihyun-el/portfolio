가수의 노래를 실시간으로 듣고 악보 위의 위치를 추정해, 그 위치에 맞춰 피아노 반주를 재생하는 온디바이스 엔진

## 문제 재정의

자동 채점이 프로 성악가에게도 낮은 박자 점수를 준 원인은 고정된 반주와의 일치를 쟀기 때문. 채점 공식 대신 반주가 가수를 따라가는 엔진으로 문제를 바꿈

자동 채점의 기준을 먼저 고민하던 단계에서, 실제 연습에 필요한 것은 사람에게 반응하는 반주라고 문제를 다시 잡았습니다. 위치 추정 모델과 반주 제어를 나누고, 쉼 뒤 재진입이나 순간적인 피치 오류를 반주 전체의 점프로 바꾸지 않도록 설계했습니다.

## 모델

마이크 소리와 직전에 낸 반주를 **12채널 × 360빈** 입력으로 받아 보컬 피치를 추정하는 신경망을 설계·학습. iOS 신경망 가속기에서 실행

신경망 본체는 가속기에서 돌리기 위해 고정 크기의 창을 받습니다. 엔진이 최근 컬럼을 보관해 창을 조립하고, 앱은 모델을 한 번 실행해 결과만 돌려줍니다. 창 모양이 고정이라 곡 시작에는 창이 찰 때까지 출력을 내지 않습니다.

## 출력 분리

가수의 실제 진행, 모델의 추정 위치, 반주 재생 위치를 세 개의 시계로 나눠, 추정이 흔들려도 반주가 자기 박자를 유지하게 설계

가수의 위치를 추정하는 모델이 정확해도 그 추정치를 그대로 반주 재생에 반영하면 음악이 자연스럽게 이어지지 않을 수 있습니다. 추정이 순간적으로 흔들릴 때 반주까지 같은 위치로 뛰면 연주자가 다시 맞출 기준도 사라집니다.

가수의 실제 진행, 모델이 추정한 위치, 반주가 재생 중인 위치를 분리했습니다. 반주는 추정을 참고하되 자신의 진행 기준을 갖도록 설계했습니다. 긴 쉼 뒤에 사람이 반주를 듣고 다시 들어오는 상황까지 고려한 결정입니다.

## 입출력 계약

오디오 콜백 한 번이 엔진을 한 번 통과. 단계마다 입력과 출력의 형태, 실패 방식까지 계약으로 고정

오디오 콜백 한 번이 엔진을 한 번 통과합니다. 앱은 마이크 소리와 직전에 낸 반주를 넘기고, 엔진은 같은 길이의 반주 소리와 커서 위치를 돌려줍니다. 그 사이에 모델용 32kHz와 합성용 44.1kHz를 거쳐 장치 샘플레이트로 돌아오고, 신경망 추론을 위해 앱과의 경계를 한 번 왕복합니다.

단계마다 입력과 출력의 형태, 지켜야 할 규칙을 정했습니다. 계약이 어긋나면 절반만 조용히 동작하지 않고 바로 드러나도록 실패 방식까지 계약에 넣었습니다.

## 실기기 문제 추적

저전력 모드에서만 소리가 끊기는 문제를 기기 내부 파일 로그로 계측. 첫 가설은 실험으로 기각하고, 겹치는 입력 창에서 두 프레임을 함께 뽑아 가속기 호출을 절반으로 줄여 아이폰 17에서 해소

신경망 본체는 CPU 폴백과 가속기 경로를 따로 측정했고, 한 창에서 프레임 두 개를 추출해 블록당 ANE 호출을 2회에서 1회로 줄였습니다. 아이폰 17의 저전력 모드에서 발생하던 잡음을 팀을 나오기 전에 해결했습니다.

## 검증

곡 전체 **9,392개 시점**에서 Python 참조 구현과 Rust 이식의 출력이 비트 단위로 같음을 확인. Rust는 AI 에이전트가 구현하고 참조 결과와 대조해 검수

문제 정의, 모델 설계와 학습, Python 참조 구현, 검증 기준을 맡았습니다. Rust 구현은 AI 에이전트와 협업했고, 참조 결과와 이식 결과를 대조해 검수했습니다. 수치 지표는 진단에 사용하고 실제 반주의 자연스러움은 청취로 확인했습니다.

| 비교 | 판정 기준 | 확인한 내용 |
|---|---|---|
| Python 제어 수학 ↔ Rust 이식 | 9,392틱 비트 동일 | 제어 수학 이식의 출력 보존 |
| Python 앞단 ↔ 이식 앞단 | 허용오차 1e-5 | 앞단의 수치 차이를 정한 범위 안에서 확인 |
| 창 전체 계산 ↔ 증분 계산 | 비트 동일 | 반복 계산을 줄이면서 기존 계산값 보존 |

같은 출력이 나왔다는 말에도 비교 대상이 다릅니다. 이 구분을 검수 기준으로 삼아 AI가 작성한 이식 코드의 동작을 확인했습니다. [검증 범위를 쓴 개발 기록](/writing/validation-boundaries/)에서도 같은 기준을 설명합니다.
