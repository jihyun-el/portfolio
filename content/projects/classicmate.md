## 개요

클래식 연주자를 위한 연습·커뮤니티 서비스입니다. 2025년 9월부터 2026년 7월까지 초기팀에 풀타임으로 참여해 개발총괄을 맡았고, 세 부분을 개발했습니다.

| 부분 | 하는 일 | 스택 |
|---|---|---|
| [반주 엔진](#engine) | 가수의 노래를 마이크로 받아 악보 위 위치를 10ms마다 추정하고, 그 위치에 맞춰 피아노 반주를 재생 | Python · PyTorch · Core ML · Rust |
| [악보 파이프라인](#pipeline) | MusicXML에서 12개 조의 PDF 악보·반주 MIDI·커서 좌표와 곡 해설을 생성 | Python · verovio · music21 · Gemini API |
| [모바일 앱](#app) | 악보 열람과 필기, MIDI 반주, 기기 간 동기화, 인앱 결제 | Dart · Flutter · Supabase |

## 부분별 문제와 구조

| 부분 | 문제 | 구조 |
|---|---|---|
| 반주 엔진 | 추정 위치를 그대로 재생하면 추정이 흔들릴 때 반주도 흔들림 | 가수 위치·추정 위치·재생 위치를 분리. 재생 위치는 템포를 적분하고 추정 위치는 가중치만큼만 반영 |
| 악보 파이프라인 | 조판 좌표와 MIDI 시각이 서로 다른 도구에서 나옴. 읽지 못한 값을 기본값으로 채우면 LLM이 사실로 받음 | 음표 시각을 music21 기준으로 통일. 읽지 못한 값은 결측으로 전달 |
| 모바일 앱 | 기기마다 다른 필기 좌표, 계정 전환 때 남는 캐시, 결제 중복 | PDF 원본 좌표 저장과 페이지 단위 병합. 잔액과 소유권은 서버만 변경 |

## 개발 방식

Python과 Dart는 직접 읽고 씁니다. 모델 설계와 학습, 검증 기준을 맡았고 Rust 이식은 AI 코딩 에이전트가 작성했습니다. 에이전트가 작성한 코드는 Python 참조 구현의 출력, 고정한 기준 출력, 실기기 동작과 대조해 검수했습니다.
