## 악보의 입력부터 사람에게 반응하는 재생까지

ClassicMate 초기팀에서 2025년 9월부터 2026년 7월까지 개발총괄로 참여했습니다. 악보를 보고 필기하며 연습하는 Flutter 앱, 앱에 악보와 반주 자산을 공급하는 Python 파이프라인, 가수의 진행에 반응하는 온디바이스 반주 엔진을 개발했습니다.

세 부분에서 다룬 문제는 서로 이어졌습니다. 악보의 좌표와 MIDI의 시각이 다르면 앱의 커서가 잘못된 페이지를 가리킵니다. 앱의 계정 경계가 흐리면 기기에 남은 캐시가 다른 사용자의 데이터로 넘어갑니다. 위치 추정이 정확해도 이를 반주 재생에 그대로 반영하면 사람이 다시 맞출 음악적 기준이 흔들립니다.

## 내가 내린 주요 결정

| 부분 | 해결해야 했던 문제 | 선택한 구조 |
|---|---|---|
| 반주 엔진 | 추정한 위치와 자연스러운 반주 재생의 충돌 | 가수·추정·재생의 세 시계를 분리하고 사람의 반응까지 고려 |
| 악보 파이프라인 | 조판 좌표와 연주 시각의 불일치, 결측 정보의 오염 | 도구의 책임과 시간축을 나누고 없는 정보는 결측으로 유지 |
| 모바일 앱 | 필기 동기화·계정 전환·결제 중복의 데이터 경계 | PDF 원본 좌표, 페이지별 병합, 서버 기준 소유권과 거래 처리 |

Python·Dart를 직접 읽고 쓰며, 모델 설계·학습·검증 기준을 맡았습니다. Rust 이식은 AI 에이전트와 협업했습니다. 구현을 맡긴 부분도 Python 참조 결과, 결정적 출력, 실기기 동작과 대조해 검수했습니다.
