# 녹음 재생 시험이 실제 연주와 달랐던 문제

가수가 반주를 듣고 부르는 실제 조건을 녹음 재생으로는 시험할 수 없어, 가상 가수와 실시간 시험 프로그램을 만들고 그 시험이 실제를 대신하는지 확인한 기록입니다.

## 문제

엔진이 실제로 쓰이는 조건에서는 출력이 다시 입력에 영향을 줍니다. 가수는 반주를 듣고 부르고, 그 노래가 다시 엔진으로 들어옵니다. 긴 쉼 뒤에는 가수가 반주를 듣고 다시 들어옵니다.

변경마다 사람이 직접 부르는 시험을 할 수는 없어 대부분의 실험은 녹음을 재생해서 했습니다. 녹음 속 가수는 엔진의 반주를 듣지 못하므로, 녹음 재생에서 통과한 변경이 실제 연주에서도 동작하는지는 이 시험으로 확인할 수 없었습니다.

## 시도 1: 녹음을 편집하기

녹음에서 노래 일부를 지우고, 다시 들어오는 지점은 엔진의 반주에 맞춘다고 가정했습니다. 반주가 가수보다 앞질러 예측하는 구조는 가수가 빨라지면 반주가 더 빨라지는 양의 피드백으로 발산하므로, 시험하기 전에 따져서 버렸습니다.

이 단계에서는 녹음의 정답 곡선과의 오차를 줄이는 것을 목표로 삼았고, 남은 1초 남짓한 지연은 실제 연주에서 사람이 맞춰 준다고 가정해 반주 제어 로직을 고정했습니다.

## 시도 2: 반주를 듣는 가상 가수

반주에 반응하는 가상 가수를 넣자 그 가정이 틀렸다는 결과가 나왔습니다. 반주가 계속 0.82초 늦자 가수가 반주를 기다렸고, 반주는 늦어진 가수를 다시 따라가 둘이 함께 17초 느려졌습니다. 가수가 맞추는 동작이 지연을 누적시켰습니다. 템포 추정을 바꾸고, 다음 음을 미리 예약해 재생하는 방식으로 옮겼습니다.

반주 박자에 맞춰 다시 들어오는 가상 가수로는, 가수가 정확히 들어왔는데도 엔진이 25초 동안 따라잡지 못하는 문제를 찾았습니다. 녹음에서만 생기던 현상을 막으려고 붙였던 보정들도 이때 제거했습니다.

## 해결 1: 사람이 직접 부르는 실시간 시험 프로그램

엔진을 Rust로 먼저 옮기는 선택지도 있었습니다. 확인되지 않은 것은 엔진 구현이 아니라 실제 연주에서의 동작이었고, 코드를 바꾸고 다시 들어 보는 주기는 Python이 짧았습니다. 마이크와 스피커까지 연결한 실시간 시험 프로그램을 먼저 만들고, 녹음 재생은 기존 결과와 같은지 보는 회귀 검사로 남겼습니다.

첫 시험에서 블록 처리 시간이 블록 길이(20ms)의 3배를 넘어 500블록 중 488블록이 밀리고 소리가 끊겼습니다. 구성 요소별로 시간을 재 보니 병목은 피치 신경망이 블록마다 64프레임 입력을 통째로 다시 추론하는 부분(약 50ms)이었습니다. 층마다 지난 계산을 캐시해 새 프레임만 계산하도록 바꾸고(출력은 전체 계산과 1e-6 이내로 같음), 입력 구간 축소 등을 더해 블록당 72ms를 16.3ms로 줄인 뒤 다시 불렀습니다.

## 해결 2: 기기에 녹음을 직접 넣기

기기에서 위치 추정 오류를 재현할 때도 같은 문제가 있었습니다. 모델은 스피커에서 나온 소리를 가수로 잡지 않도록 학습했으므로, 녹음을 스피커로 틀어서는 시험할 수 없습니다. 녹음된 목소리를 마이크 입력 자리에 직접 넣는 장치를 만들었습니다.

시험 프로그램 자체의 오류도 찾았습니다. 실제 연주를 흉내 낸 조건을 네 가지로 바꿔도 결과가 완전히 같은 것을 보고, 반주가 입력과 상관없이 자기 템포로만 진행한다는 것을 찾았습니다. 전날 측정에도 같은 오류가 들어 있었습니다. 녹음 재생 경로는 0.5초 쉼을 정상으로 넘겼지만, 기기에서는 템포가 0.2배로 떨어지고 4초 뒤처졌습니다. 기기의 신경망 출력을 맥의 Rust 실시간 경로에 그대로 넣어 재현하고 Python 원본과 프레임별로 대조해, Rust 실시간 경로가 옥타브 검출과 시간 버퍼를 포함한 배포 설정 다섯 개를 빠뜨린 것을 찾아 맞췄습니다. 맥 재현에서 쉼 구간의 최저 템포가 0.17배에서 1.05배가 됐습니다.

## 결과

- 가상 가수 시험: 가수가 정확히 다시 들어온 뒤 엔진이 따라잡는 데 걸린 시간 25초 → 0초
- 실시간 시험 프로그램: 블록 처리 시간 72ms → 16.3ms (블록 길이 20ms), 처리 시간이 블록 길이를 넘은 블록 98% → 1%
- 사람이 부른 시험: 멜로디를 제대로 부르지 않은 테이크에서는 추정이 가수를 따라가지 못했고, 제대로 부른 테이크 하나에서는 전체의 67% 동안 가수를 따라가며 0.49~1.14배의 템포 변화에 맞춤

## 남은 한계

가상 가수가 반주에 반응하는 방식은 가정으로 만든 모델이고, 사람이 부른 테이크는 몇 개였습니다. 대체 시험을 쓸 때는 입력을 바꾸면 결과도 바뀌는지를 먼저 확인합니다.
