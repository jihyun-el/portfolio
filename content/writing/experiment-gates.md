# 점수를 보기 전에 정한 것과 본 뒤에 고른 것

VQA 대회에서 채택 기준을 Public 점수를 보기 전에 정하고, 점수를 본 뒤 고른 선택은 따로 기록한 다음, Private 결과로 두 쪽을 다시 확인한 기록입니다.

## 문제

Public 리더보드는 test의 절반(3,357문항)으로 채점하고 하루 20회까지 제출할 수 있습니다. 점수를 본 뒤 방법을 고르면 답안이 Public에 맞춰질 위험이 있습니다. 5인 팀이 각자 다른 조건에서 출발하면 어느 변경에서 이득이 났는지도 알 수 없습니다.

## 방법 1: 출발점과 분할을 고정

같은 모델 출발점과 이미지 단위 분할을 팀 전체가 공유하고, 모델 크기와 해상도 같은 축을 하나씩 나눠 실험했습니다. 4B/8B와 512²/768²는 네 조건을 모두 제출해 두 효과를 따로 쟀습니다.

## 방법 2: 실제로 실행된 값을 확인

팀원의 1시간 학습 결과가 기존 모델과 점수가 소수점까지 같아 adapter 해시를 대조했고, 학습 코드가 설정의 해상도 대신 512² 고정값을 쓰는 버그를 찾았습니다. 이후 학습을 시작할 때 실제 입력 해상도를 출력하고, 모델 해시를 대조하고, 큰 실행 전에 CPU에서 실행 경로를 검사하도록 바꿨습니다.

## 방법 3: 채택 기준을 결과 전에 커밋

추론 방식을 더할 때는 자체 검증 세트의 앞·뒤 절반 모두 손해가 없고 전체가 1문항 이상 늘 때만 채택했습니다. 타일링, 추가 에폭처럼 기각한 실험도 결과와 함께 남겼습니다.

최종 두 답안 중 하나는 미리 정한 로그 확률 평균 규칙으로 만들었고, 다른 하나에는 Public 점수를 본 뒤 고른 결합이 들어갔습니다. 두 답안을 그렇게 구분해 기록했습니다.

## 결과: Private으로 다시 확인

| 변경 | Public | Private |
|---|---|---|
| 해상도 512² → 768² | +134문항 | +133문항 |
| 모델 4B → 8B | +75문항 | +79문항 |
| 마지막 이어 학습 | +3문항 | −3문항 |

결과 전에 채택한 큰 변경은 Private에서도 크기가 같았고, 3문항 차이로 채택한 변경은 방향이 바뀌었습니다. Private 0.97855를 낸 것은 Public을 보고 고른 결합이 들어간 답안이었고, 규칙으로 만든 답안은 Private 0.97795로 2문항 차이였습니다.

저장된 예측 CSV 54개에서 최종 두 답안을 다시 계산했고, 저장된 CSV와 SHA-256이 일치했습니다.
