# 점수를 보기 전에 정한 것과 본 뒤에 고른 것

VQA 대회에서 비교 기준을 결과 전에 정하고 Public을 본 뒤 고른 선택은 따로 기록했으며, Private 결과로 두 쪽을 다시 확인했습니다.

## 비교할 출발점 하나

5인 팀이 각자 다른 조건으로 출발하면 어느 변경에서 이득이 났는지 설명하기 어렵습니다. 같은 모델 출발점과 이미지 단위 분할을 공유하고, 모델 크기·해상도 같은 축을 나눠 실험했습니다. 4B/8B와 512²/768²의 네 조건을 교차 비교해 두 효과를 분리했습니다.

## 실행한 조건도 확인하기

설정에서 해상도를 바꿨는데 실제 학습 코드가 고정값을 쓰고 있었습니다. 팀원의 실행이 같은 adapter를 만든 뒤, 파일의 의도보다 실제 입력값을 확인하는 검수가 필요하다는 것을 알았습니다. 실제 해상도 출력, 모델 해시 대조, 큰 실행 전 CPU 경로 감사를 보강했습니다.

## 효과가 없는 실험을 남기는 이유

추론 변경의 채택 기준은 자체 검증의 앞·뒤 절반 모두 손해가 없고 전체가 1문항 이상 좋아지는 것이었습니다. 타일링이나 추가 에폭처럼 기대한 효과가 없던 실험도 기록했습니다. 최고 점수 파일만 남기면 시도한 수와 실패한 방향이 사라집니다.

모든 최종 선택이 사전 규칙을 따르지는 않았습니다. 최종 두 답안 중 하나는 Public 결과를 본 뒤 고른 결합이 포함됐고, 다른 하나는 미리 정한 로그 평균 규칙이었습니다.

## Private에서 다시 본 기준

Private 점수가 공개된 뒤 같은 기준으로 다시 확인했습니다. 0.97855를 낸 것은 Public을 보고 고른 결합이었고, 규칙으로 만든 답안과는 2~4문항 차이였습니다. 결과 전에 채택한 큰 변경은 Private에서도 크기가 같았습니다. 해상도 512²→768²는 Public +134문항·Private +133문항, 모델 4B→8B는 +75·+79문항이었습니다. 반대로 Public에서 3문항 차이로 채택한 마지막 이어 학습은 Private에서 −3문항이었습니다. 큰 차이는 그대로 남았고, 몇 문항 차이는 방향이 바뀌었습니다.

## 다시 만들 수 있는 답안

저장된 예측 CSV 54개에서 최종 두 답안을 다시 계산했고 저장된 CSV와 SHA-256이 일치했습니다. 제출 묶음 안에서 초반 다수결부터 최종 결합까지 모든 단계를 다시 계산할 수 있습니다.
