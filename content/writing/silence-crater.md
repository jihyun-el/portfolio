# 반주 템포가 급락하던 문제

가수가 쉬거나 음을 틀린 순간 반주 템포가 0.3배까지 떨어지던 문제를, 켜고 끄는 조건 대신 연속 가중치로 바꿔 해결한 기록입니다.

## 문제

새로 학습한 피치 모델로 실제 녹음을 돌리다가, 가수가 쉬는 구간에서 반주 템포가 0.3배까지 떨어지는 것을 들었습니다. 쉬는 동안 반주는 자기 템포로 이어 가야 합니다.

## 원인: 세 번 틀리고 프레임별 기록을 남겼다

순간 이동, 템포 추정의 하한, 평상시 동작 순으로 원인을 추측했지만 모두 틀렸습니다. 엔진의 상태를 프레임마다 기록하고서야 원인이 보였습니다. 쉬는 구간의 불분명한 피치가 짧은 잘못된 확정을 냈고, 엔진은 가수가 돌아왔다고 보고 위치를 다시 맞추는 상태로 들어갔습니다. 가수는 계속 쉬고 있어서 추정 위치는 멈춰 있었고, 반주는 그 멈춘 위치 쪽으로 보정되며 템포가 떨어졌습니다.

## 시도 1: 쉬는 동안 위치 보정 끄기 — 실패

깊게 떨어지는 현상은 사라졌지만 멈춤과 떨림이 새로 생겼습니다. 위치 보정에는 반주가 추정에서 너무 멀어지지 않게 막는 역할도 있었습니다. 이것까지 꺼지자 간격이 최대 5.77초로 벌어졌고, 다시 맞출 때 57프레임 동안 멈췄으며 가속도 변화율(저크)은 45배로 뛰었습니다.

## 해결 1: 들어갈 땐 신중하게, 나올 땐 즉시

최근 구간에서 소리가 충분히 이어졌을 때만 위치를 다시 맞추고, 맞추는 도중 정보가 끊기면 바로 그만두게 했습니다. 소리가 연속으로 나야 한다는 조건은 한 프레임만 끊겨도 다시 맞추는 시점이 12.4초 밀렸지만, 구간 안에서 소리가 난 프레임 수를 세는 방식은 자음이나 숨으로 생기는 짧은 끊김을 견뎠습니다. 그만두는 조건까지 느슨하게 하면 같은 문제가 다시 생겼습니다.

가수가 잡담하다 77초부터 다시 노래한 녹음에서, 잡담 동안 반주 템포는 일정했고 노래가 다시 시작된 지점에서만 위치를 다시 맞췄습니다. Python, 실시간 시험 프로그램, Rust 세 구현에 같은 결과로 넣었습니다. 실제 기기 연주 기록 세 개에는 긴 잡담이 없었고, 이 수정으로 바뀐 출력은 한 프레임도 없었습니다.

## 다시 나타난 템포 급락

기기에서 고음이나 틀린 음이 들어올 때 템포가 0.19배까지 떨어졌습니다. 피치 모델을 고치는 방법은 이미 다 시도한 뒤라 모델은 고정하고, 엔진이 틀린 피치에 영향받지 않게 하기로 했습니다.

Python에 피치 오류를 넣어 봤지만 재현되지 않았습니다. 기기 테스트를 위해 Rust 쪽에서만 위치를 다시 맞추는 조건을 되돌려 둔 상태였기 때문입니다. 측정은 실제로 배포되는 경로에서 해야 했습니다. 조건을 되살리는 것만으로도 부족했습니다. 6월 20일 수정판도 실제 녹음에서 템포가 0.7배 아래로 떨어진 프레임이 559개였습니다.

## 시도 2: 조건의 값 바꾸기 — 실패

조건을 켜고 끄거나 문턱값을 바꿔도 결과는 거의 같았습니다. 추정 위치가 앞으로 갈 때만 위치를 맞추는 조건은 실제 녹음에서 실패했습니다. 추정 위치가 멈추지 않고 0.61배 속도로 뒤처지며 전진해 조건을 통과했기 때문입니다. 문제는 값이 아니라 켜고 끄는 형태였습니다.

## 해결 2: 연속 가중치

위치 보정의 가중치를 확신도와 "관측이 예상 진행과 맞는 정도"를 곱한 연속 값으로 바꿨습니다. 관측이 예상한 진행에서 멀수록 가중치를 낮추고, 가중치가 0이 되면 반주는 자기 템포로 진행합니다. 확신도만으로는 부족했습니다. 템포가 떨어진 프레임의 42%는 확신도가 높은데도 뒤처진 관측이었습니다.

이렇게 바꾸자 여러 상태를 오가던 상태 기계가 필요 없어졌습니다. 상태 기계는 연속적인 값을 몇 단계로 나눠 근사한 것이었습니다.

## 결과

- 1배속 반주에 맞춰 부른 실제 녹음(정답은 처음부터 끝까지 1배속)에서, 0.7배 아래로 떨어진 프레임이 559개에서 0개가 됐습니다. 조건을 되돌린 버전은 1,439개였고, 새 방식의 최저 템포는 0.72배였습니다.
- 실기기에서 청취로 확인했습니다. Python과 Rust는 한 곡 전체(9,392프레임)에서 비트 단위로 같았고, 이전 상태 기계는 배포 빌드의 컴파일 대상에서 제외했습니다.

## 남은 한계

0이라는 숫자에는 함정이 있었습니다. 같은 녹음에서 52초 이후 보정 가중치가 0으로 떨어져, 템포는 매끄러웠지만 위치는 7초 뒤처졌습니다. 템포 지표만 봤다면 놓쳤을 문제로, 위치 그래프를 보고서야 알았습니다.

위치를 다시 맞추는 장치는 만들지 않았습니다. 녹음을 재생하는 실험에서는 가수가 우리 반주를 듣지 못하지만, 실제 사용에서는 가수가 반주를 듣고 맞춥니다. 그래서 녹음 실험에서 생긴 위치 차이는 고칠 대상이 아니라고 판단했습니다.
