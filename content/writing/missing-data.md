# 템포를 읽지 못한 곡에 120BPM이 들어가던 문제
<!-- home: hidden -->

악보에서 읽지 못한 템포를 기본값 120BPM으로 채우던 처리가 LLM 곡 해설의 전제가 된 문제를, 읽지 못한 값은 결측으로 넘기도록 고친 기록입니다.

## 문제

첫 구현은 MusicXML에서 템포를 읽지 못하면 MIDI 표준 기본값인 120BPM을 넣었습니다. 당시 배치 820곡 중 674곡에 이 값이 들어갔습니다. 곡 해설을 만드는 LLM은 악보에 적힌 템포와 프로그램이 채운 템포를 구분할 수 없어, 120BPM을 확정된 템포로 받아 연습 안내를 생성했습니다.

## 원인

악보 특성을 추출하는 함수가 값을 읽지 못하면 빈 값 대신 기본값을 반환하는 구조였습니다. 같은 형태를 모두 찾으니 세 곳이 더 있었습니다. 박자는 `4/4`, 마디 수는 1, 조성은 `C major`였습니다.

## 해결

2026년 2월 15일에 기본값을 모두 없애고 규칙을 정했습니다.

- 읽지 못한 값은 빈 값으로 반환
- LLM 프롬프트에는 "악보에 명시되지 않음"으로 표시
- 조성처럼 없으면 진행할 수 없는 값은 그 곡만 실패로 처리하고 배치는 계속 진행

## LLM 출력 쪽의 조치

Gemini 처리를 사실 수집, 구조화, 코칭 세 단계로 나누고, 코칭의 연습 과제마다 근거 필드(`basis`)를 요구했습니다. 악보에서 계산한 박자·템포·마디 수·음역은 프롬프트에 넣어 기준으로 삼게 했습니다. 생성 뒤에는 항목 수, 연습 시간 합계, 빈 근거를 규칙으로 검사하고, 어긋나면 경고를 기록합니다.
